01 / WHY HEARTH

问题不在模型，
而在模型之外。

Hearth 的起点不是再做一个更聪明的 Agent，而是承认：一次漂亮的演示，和一件可以长期托付的工作，是两回事。

01

状态只活在聊天里

崩溃、重启或换设备后，任务上下文和执行进度无法可靠恢复，只能重新讲一遍。

02

副作用没有账本

发邮件、改文件、提交代码缺少审批、幂等与回执，失败后很难对账，更不敢放手。

03

权限与记忆没有边界

凭据、个人上下文和工具权限混在一起，用户无法判断 Agent 到底能做什么。

04

每次都从零开始

上下文与 Token 成本不可控，成功经验也无法沉淀成可评估、可回滚的技能。

ONE-SENTENCE DEFINITION

Hearth 是一个拥有个人上下文、持久执行、真实工具和多设备入口的通用个人 Agent OS。

它的目标不是制造另一个需要看管的聊天窗口，而是让重复的数字劳动可以被放心地托付、验证和恢复。

  • 单用户为一个人的真实工作流设计，不做企业多租户。
  • 本地优先身份、状态与凭据尽量留在自己的设备上。
  • 执行器并列Codex 是强大的执行器之一，不是产品本体。

02 / SYSTEM

一个逻辑 Agent，
七个协作平面。

Hearth 不让某个模型成为系统本体。控制面决定做什么、是否允许、何时打扰；持久执行内核负责恢复和证据；执行器只是可替换的能力层。

所有事实进入 Event Log；所有外部副作用经过 outbox、幂等键和 Receipt；所有界面状态都是投影，而不是事实源。

设计不变量

任务可以换执行器，设备可以换位置，模型可以换供应商；但事实源、授权边界和恢复路径不能变。

  1. 01

    Experience Plane

    任务卡 · 审批 · 产物 · 接管

  2. 02

    Personal Gateway

    身份 · 渠道 · 设备 · 注意力入口

  3. 03

    Control Plane

    触发 · 策略 · Mandate · 调度 · Watchdog

  4. 04

    Durable Harness

    任务图 · 预算 · lease · 重试 · 恢复

  5. 05

    Executor Layer

    Native · Codex · Connector · Browser · GUI · Human

  6. 06

    Execution Gateway

    工作区 · Sandbox · 网络 · Credential Broker

  7. 07

    Memory / Evolution

    个人上下文 · 记忆 · 技能 · 评估 · 回滚

事件是事实源 · 副作用有回执 · 界面只是投影

03 / DESIGN CHOICES

四个不能妥协的设计选择。

这些选择决定了 Hearth 不是“给 Codex 套一层界面”，而是一套能长期运行、能被验证的个人基础设施。

01

任务控制面

先定义任务、授权与风险，再选择谁来执行。该不该做，永远不由执行器自己决定。

02

持久执行

崩溃、断网、休眠或换设备后继续，而不是从零开始；每次失败都留下原因和恢复路径。

03

并列执行器

按能力、风险和 Token 成本选择 Codex、Connector、Browser、GUI 或 Human，而不是把所有工作塞进一个循环。

04

记忆与进化

让经验可被安全召回，但写入、晋升与回滚都必须有边界、有来源、有评估。

04 / TASK FLOW

从一句话，
到一份可验证的回执。

用户不需要理解 Harness、Ticket 或 WorkerEvent。系统需要保证的是：现在发生了什么、是否需要你、失败后怎么继续。

  1. 01

    意图

    用户、定时任务或外部事件产生输入。

  2. 02

    任务卡

    把意图变成清晰的目标、范围与主动作。

  3. 03

    授权

    策略、预算与审批决定这次能做什么。

  4. 04

    执行

    选中的执行器在受限环境里工作，持续写入事件。

  5. 05

    验证与恢复

    判断完成、重试、换执行器或转人工，并留下回执。

05 / ROADMAP

七个阶段，
一条能力阶梯。

路线图按能力门槛推进，不以日期承诺。每个阶段都必须同时有用户可见界面、持久状态、验证证据和恢复路径。

  1. Stage 0原型与契约当前起点 · 产品楔子、点击原型、schema v0
  2. Stage 1本地 MVPhearthd、SQLite、Event Log、Codex、审批与产物
  3. Stage 2日常操作员邮件、日历、文档、网页、数据的真实任务
  4. Stage 3桌面操作员GUI 执行、设备 agentd、接管与桌面隔离
  5. Stage 4主动个人 AgentTrigger、注意力预算、手机 PWA 与设备配对
  6. Stage 5记忆与进化 OSMemory OS、技能评估、晋升与回滚
  7. Stage 6Personal Agent OS v1.0多设备同步、迁移、长期运行与配额

Stage 0 的目标不是写更多文档，而是把原型、交互、协议和验收钉住。
