WHY CAIRN NOTES / 为什么做

不是把资料搬过来，
而是把读懂的东西留下来。

“Cairn”是旅人留在路上的石堆。它不替你走路，只告诉你：这里有人走过，方向大致可信。这个站点也一样，最初是给自己的学习留标记，后来慢慢变成一份可以公开阅读、质疑和纠正的系统地图。

所以这里的更新速度不会很快。一套笔记要绑定明确的 release 与 commit，给出真实问题、调用链、实验记录和失效边界，才会从私人草稿变成公开页面。

固定版本 · 沿调用链阅读 · 用实验和证据校验结论

CURRENT COLLECTIONS / 现在收录什么

从 Agent 如何工作，
到它的动作在哪里安全发生。

两套深读不是互不相干的资料集合，它们共同回答一个问题：模型怎样可靠地做事，又怎样被边界约束。

从一次模型调用开始，拆开 Agent 的循环、上下文、工具、扩展、模型适配和多形态入口，最后亲手重建一个 mini agent。

学完得到什么

一套可以迁移到其他 Agent 项目的完整心智模型，以及一个能解释设计取舍、测试和失败边界的 mini agent。

INSIDE THE NOTES / 页面预览

打开之后，会看到真实的系统拆解。

HOW TO READ / 阅读方法

先知道在读哪一版，
再问它为什么成立。

  1. 01

    固定版本

    每套笔记对标一个明确的 release 与 commit。版本先行，讨论“支持”才有意义。

  2. 02

    沿链路阅读

    不按目录逐文件通读，而是追一次请求或任务如何穿过系统，每层只回答一个关键问题。

  3. 03

    标注边界

    把“命令存在”“本机验证”“需要集群”分开写。能指出结论在什么条件下失效，才算真正理解。

PUBLIC BOUNDARY / 公开边界

只公开经得起复核的部分。

Cairn Notes 不包含上游源码、本地路径、私有配置或凭据。站点把事实错误、失效边界和未验证条件都当作内容的一部分，而不是需要藏起来的瑕疵。
